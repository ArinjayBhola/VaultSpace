# VAULTSPACE architecture

Next.js App Router on Vercel. Better Auth owns database-backed sessions; public registration is disabled. A provisioning CLI creates the sole user under a transaction and the database enforces a singleton owner. Route handlers authenticate again independently of page layouts. Mutations validate origin and Zod inputs. PostgreSQL/Drizzle is authoritative; no local filesystem persistence.

Neon stores metadata, annotations, settings, job state and search indexes. Private R2 stores originals and derived thumbnails. Browser uploads use short-lived, per-object signatures; finalization independently inspects R2 size and magic bytes. Multipart uploads use signed parts. Upload readiness and asynchronous processing are separate states.

Owner-authenticated, origin-checked `/api/operations` requests perform file operations while the app is open. PostgreSQL operation records store status and an expiring lease; they do not depend on an external execution provider. One request handles one operation; PDF preparation renders only the first-page thumbnail and records page count. Per-file lease checks serialize different generations, and generation checks prevent stale writes. Failed operations require explicit retries. Maintenance is owner-scoped and rate-limited; retention progresses on visits, with R2 lifecycle as the offline backstop. Thumbnail generation remains bounded to 50 MiB originals; files above the limit stay downloadable.

Parameterized PostgreSQL name, original-name, extension and MIME matching provide filtered and paginated file search. No document content is extracted, stored or searched. There are no model calls or vector tables.

Shares store token hashes and scrypt password hashes. Access uses a separately signed, short-lived HttpOnly grant cookie scoped to the public share. File delivery revalidates expiration, revocation and trash state. Private range reads support PDF.js. Deletion is a durable, repeatable R2-first cleanup workflow; relational metadata remains until object deletion succeeds. Application hierarchy writes use a transaction advisory lock; upload finalization also locks its upload row before copying the staging object. R2 calls are not atomic with PostgreSQL: failed finalization leaves tracked staging/original keys for repeatable cleanup. Generation checks invalidate older processing jobs, and restoring interrupted processing schedules a new generation.

Deployment target is explicitly Vercel, per product requirements. Sites Worker hosting is not used because it would change the required server runtime and deployment architecture.

Implementation sequence: foundation → verified storage → organization → PDF persistence → lexical search → AI jobs/hybrid search → sharing/recovery → analytics/settings → release checks. See IMPLEMENTATION_STATUS.md for verification, limitations and pending acceptance checks.

Activity history is owner-scoped, sorted by timestamp plus ID, and paginated in PostgreSQL (20 entries/page) through `/api/activity`. Overview shows three entries and links to `/activity`. Development starts Next.js directly; no external runner is required. Trash refreshes every three seconds, shows provider/cleanup failures, and retries failed cleanup without duplicating an already-pending current-generation job. Empty purged folders are pruned immediately and after successful file cleanup.

Migration 0005 removes the embedding table and its indexes, image caption column, AI settings columns and obsolete AI-only state. It rebuilds the metadata full-text index without captions. It drops the unused vector extension with RESTRICT, preserving unrelated dependencies if the database is shared. Historical migrations and snapshots remain for upgrade tracking; after that migration the schema had 18 tables. Migration 0006 adds viewer presence, bringing the current schema to 19 tables.

Sharing visibility uses owner-scoped, file-filtered paginated queries and real access counts. Viewer presence uses a share/viewer-hash primary key with an indexed timestamp, valid signed grants, origin checks and a per-share heartbeat rate limit. Active viewing sessions are visible tabs heard from in 45 seconds, bounded by grant/share expiry; they are not unique people. Valid active heartbeats renew the five-minute grant without incrementing access counts. Revocation removes presence rows and prevents subsequent authorization, content reads and heartbeats.

Product visual styling is centralized in `src/app/design.css`, imported after baseline global styles. Overview and sharing components reuse existing authenticated aggregation queries; presentation charts are derived from authoritative byte counts. Appearance choices use the existing device preference store; sectioned Settings preserves unsaved form state while switching URL-addressable tabs. Shared password inputs retain forwarded form refs and autocomplete behavior. No extra AI, model usage, seeded metrics or test infrastructure was introduced.

Typography preferences use the existing local preference store and a global client synchronizer. Font family and bounded size identifiers resolve through fixed allowlists to CSS custom properties on the document root. Stylesheet and inline interface font sizes share the scale, including portal content. Fontsource assets are bundled with the app; no external font API is required. This changes interface text without CSS zoom or PDF geometry changes.
